# タップ位置の切り分け・選択UI改修（2026-10-07）

## 状態

ClaudeのDDI復旧・セットアップUIのある作業フォルダをベースに改修。
ソースの確認と配布ZIPの照合のみ実施。ローカルにはSwift/Rustコンパイラがなく、コンパイル・新規テスト・実機試験は未実施。
GitHub Actionsに座標変換のRustテストを追加済み。ビルド成功を確認してから実機へ入れる。

## 変更

- AIモデルを選択式にした。3.5 Flash Lite / 3.1 Flash Lite / 3.5 Flash。既存モデル設定は保持。詳細設定で任意モデル名も入力可能。
- アプリ一覧取得後、自動的に検索・選択画面を開く。アプリ名と選択チェックを表示し、一覧を端末に保存。apps.txtのコピーは不要。
- WDAの画面サイズを対象アプリ起動後に取得し、さらに各タップ・スワイプ直前に再取得。画像全体の0〜1000座標からポイントへ変換。
- 範囲外・欠落座標、画像と画面の縦横比が3%以上違う場合は操作しない。同じ縦横比の切り抜き・180度回転などは検知できない。
- 新しいMJPEGフレームが5秒以内に届かない場合は停止。映像の内容が新しいことやAPI応答中に画面が変わらなかったことまでは保証しない。
- AIが指定した位置に赤丸を重ねてアプリ内表示。Documents/steps/step_NNN_tap.jpgにも保存。実際に端末で測定した接触位置ではない。
- ログにWDAへ送信したポイント座標と画面サイズ、結果を表示。WDA受理とゲーム進行を区別。
- 同じ付近（最初の座標から各軸15/1000以内）のタップを3回送信したら、4回目は送らず停止。waitを挟んでも継続、別位置・スワイプ・新規開始でリセット。画面変化の判定ではなく、正常な繰り返しも止める暫定ガード。
- 操作エラーは停止、429の再試行は2回まで。停止要求・本アプリ前面復帰後のAI応答は操作に使わない。

## 更新

以前のdiagnostics用パッケージを重ねない。認証ファイル・APIキー・端末データは含めていない。
ActionsからBuild unsigned iPhone probeを実行し、成功後にIPAをダウンロードして従来の方法で更新インストールする。

## 最初の実機確認

1. AI設定で3.1 Flash Liteを選べるか確認（無料枠・利用可否は利用者のAI Studioで確認）。
2. VPN接続中に「アプリを取得して選ぶ」。一覧が開き、アプリ名で選べるか確認。再起動後も一覧と選択が残るか確認。
3. OKボタン等のある場面で、まず「実際に操作する」をOFFにし、最大1手で実行。戻って「最後にAIが狙ったタップ位置」の赤丸がボタン中央にあるか確認。
4. ONで少数手の試験。反応しない場合は赤丸画像と「送信位置…pt / 画面…pt」のログを比較する。
5. 同じ場所への4回目が送られず止まるか確認。再起動後のDDI復旧とゲーム開始も回帰確認する。

赤丸が外れている場合は画像理解・正規化の問題を疑う。赤丸が合っている場合はWDAの座標系、入力受付タイミング、ボタンの当たり判定等を調べる。現段階で原因確定・修正完了とはしない。
