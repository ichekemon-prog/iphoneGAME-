## 今回の範囲

AIキー・指示文・対象アプリなしで「接続を診断する」を押せる。
既存の接続処理を使い、R0〜R8、開発用サービスの広告有無、WDA情報、WDAセッション、端末内8100への到達、9100からのJPEG受信を表示する。
失敗箇所と対処候補を残す。停止時は実行中の項目を中断とする。
診断全体は最大300秒、個々の通信にもタイムアウトを設定する。
WDA起動に伴う画面切り替えはあるが、対象アプリの起動・タップ・AI呼び出しは行わない。
受信画像をファイル保存したり、AIに送ったりしない。
認証ファイルの内容・生のサービス一覧は診断レポートに出さない。

VPNのOS状態を直接取得していない。到達失敗はVPN・IP・端末状態などを確認する案内とする。
DDI状態を直接問い合わせていない。testmanagerd等の広告有無だけで未マウントと断定しない。
JPEGは受信と開始・終了マーカーを確認する。画像復号・内容の正しさは別の検証。
結果は診断時点のもの。常時監視、切断時の自動復旧、DDIマウントは次の作業。

## 最初の実機操作は1つだけ

ビルド・通常どおりの署名と上書き後、LocalDevVPNが接続されている状態で、本体の「接続を診断する」を1回実行する。
正常な基準結果をスクリーンショットで保存する。WDA画面に移った場合は本体へ戻って結果を見る。
ここではまだiPhone再起動、署名更新、VPN切断を同時に試さない。

期待: 認証から画像受信まで確認済み。AI利用回数を消費しない。
失敗した場合: 最初の失敗行と「次の操作」を確認し、その1点を解消する。

## その後の順序

1. 正常時の診断が成立したら、VPN切断状態で診断し、失敗表示を確認。VPNを戻す。
2. 実行中に停止し、中断表示になるか確認。
3. C1: iPhone再起動→VPN接続→診断。再起動前後の差を比較。
4. C2: 開発用サービスが見えないときだけDDI調査に進む。
5. D1〜D5: 更新の実証。

現行の正常動作版に戻せるよう、元のIPAを残しておく。
