## 調査で確認した経路

- iloader公式は任意IPAの導入と、対応アプリへのペアリングファイル配置を提供する。
- src-tauri/src/pairing.rsはRemotePairingLockdownServiceでRemote Pairingを生成し、lockdown情報と合わせて配置する。
- place_fileはHouseArrestのvend_documentsからAFCで指定アプリのDocumentsに書く。
- 対応アプリはPAIRING_APPSの表示名リストで選別される。既存配布版にPhone Runner Probeはない。公式版をそのまま使うだけで自動配置できるとは言えない。

- https://github.com/nab138/iloader/blob/main/src-tauri/src/pairing.rs

## 今回用意したもの（ビルド・実機未確認）

1. setup/iloader-phone-runner.patch：対応アプリ名と配置先を追加する最小差分。PCツール完成版ではない。第三者の完成バイナリは変更・配布していない。
2. App/PairingSetup.swift：Documents/phone-runner-pairing.plistを読み、Remote Pairing形式を検証して既存のApplication Support/remote-pairing.plistへ保存。成功後に受け渡しファイルを削除。
3. 初回設定時はアプリを開く／前面へ戻すと自動取り込み。前面のまま送った場合は詳細設定の「PCから届いた設定を確認」を押せる。
4. 既存設定がある端末では自動上書きしない。検証用に現用の認証情報を削除しない。入れ替えは既存の手動インポートから明示的に行う。
5. project.ymlでCFBundleDisplayNameを明示。署名時に名前を変更するとPC側の一覧検索に一致しない。
6. tests/PairingSetupTests.swift：不正形式・lockdownのみ・鍵サイズ・上限サイズ・正常保存と受け渡しファイル削除・既存設定保護。Actionsに実行を追加。Windows環境にはSwiftコンパイラがなく未実行。

受け渡し先は一時的にファイル共有領域となる。PC側は書き込みを完了してからアプリを開く。ファイル内容をログ・成果物・リポジトリに含めない。本番PCツールでは一時ファイルへの書き込み→rename等で途中読込を防ぐ設計も必要。

## 次の検証手順

1. iPhone版のActionsビルドで新しいSwiftテスト・既存Rustテストが通ることを確認。
2. iloaderのソースを取得しコミットを固定。パッチをgit apply --checkで検証後適用し、ローカル検証版をビルド。現時点ではPC版のコンパイル環境整備・バイナリ作成は未着手。一般配布する際の名称・ライセンス条件は別途確認する。
3. まずは現用iPhoneを変更せず、一覧にPhone Runner Probeが表示されることを確認。
4. エージェント停止後、対象端末を明示してペアリング情報を配置。既存端末では設定が自動上書きされないことを先に確認。
5. 初回設定の検証端末で、自動取り込み→受け渡しファイル消去→VPN接続→通常診断まで通す。初回設定の検証端末がなければ、その項目は未確認のまま残す。

Appleアカウントのログイン・署名・WDA再導入は、この認証受け渡しの検証では行わない。
